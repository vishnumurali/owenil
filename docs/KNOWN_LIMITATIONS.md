# Known limitations

- **No payments or subscriptions.** Owenil Plus is enabled only through the development entitlement (testers mode). Prices on the Plus page are for display only.
- **No OCR.** Receipt details and items are entered manually. Local OCR (for example `tesseract.js`, Apache-2.0) could be added later. It's free but adds about 10 MB of assets, so it was left out of the MVP.
- **UPI payments aren't verified.** Owenil only opens the payer's UPI app with the details filled in (or shows a QR code). UPI apps report the result only to native Android apps that start the payment, never to websites, so on the web Owenil asks "Did it go through?" when the payer returns and records it on "Yes". The Android app reads the UPI result: **Pay with GPay** marks a payment paid automatically when Google Pay reports success. Some UPI apps decline or warn about app-started payments to personal UPI IDs; scanning a QR code inside the UPI app still works. Confirmed payments would need a payment gateway with merchant KYC and fees, which doesn't fit person-to-person repayments. UPI is INR-only and apps usually cap a person-to-person payment at ₹1,00,000. Some UPI apps warn about or limit payments started from links; scanning the QR code from inside the app is the fallback.
- **Combined payments and offsets.** When you pay someone everything at once and they also owe you in another group, Owenil records that part as an offset (method "Other") so every balance with them ends at zero and the money that moved equals the total shown.
- **No live exchange rates.** Conversion uses only rates the user records. This is deliberate.
- **Email delivery.** Supabase's built-in email only reaches your own team's addresses and sends at most 2 emails an hour. `npm run supabase:provision -- --smtp` switches auth emails (sign-up confirmation, password reset) to a Gmail account with an app password: free, about 500 emails a day, sent from that Gmail address. Until that's set up, email confirmation stays off. Invitations are links you share yourself (WhatsApp, SMS, email); Owenil doesn't send invite emails.
- **Phone numbers aren't verified.** Sign-up asks for a mobile number so friends can find you, but there's no SMS code (OTP) check yet, because no phone-OTP service is free for real users: Firebase phone sign-in needs a paid (Blaze) billing account at about US$0.06–0.07 per SMS in India; Indian SMS gateways such as MSG91 cost about ₹0.15–0.25 per SMS plus GST and DLT sender registration; WhatsApp OTP costs about ₹0.12 per message plus GST. Each number belongs to one account, first come first served. Finding people reveals that a number or email is on Owenil only to someone who already knows it, never the number or email itself, and anyone can turn finding off in Privacy. Adding a stranger sends a friend request they must accept.
- **Contacts.** "Find friends from contacts" exists only in the Android app (websites can't read a phone's contacts). Contacts are compared as SHA-256 codes; phone-number codes can in principle be reversed by trying every number, so the protection is against casual exposure, not a determined server operator. Nothing is stored. Google Contacts on the website would need Google's verification of a sensitive scope, so it isn't offered there.
- **Realtime.** Lists refresh on actions, on focus and every 60 seconds (notifications). They don't stream live changes yet; Supabase Realtime could be added.
- **Itemized edits by non-Plus users.** Changing an existing expense *to* itemized requires Plus. An expense that's already itemized can still be edited by anyone allowed to edit it.
- **Recurring templates with several payers or exact amounts** can't change their amount. Cancel and recreate instead; other fields can be edited.
- **Leaving with a balance.** Members can't leave or be removed, and accounts can't be deleted, until balances are settled. This is intentional so others' records stay correct.
- **Account deletion and auth.** `delete_my_account` anonymises all data. It also removes the `auth.users` row when the database role is permitted to; if not, the profile is anonymised and the login stays until an admin deletes it in **Authentication → Users**. The result tells you which happened.
- **Scale.** Some list views compute in the browser: balances, analytics over at most 10 years of the caller's own expenses, and group insights over at most 1,000 expenses. That's fine for personal and group use. Move them into SQL views if a group grows very large.
- **Static hosting.** GitHub Pages can't send security headers, so the CSP is a meta tag and framing is blocked by script rather than `X-Frame-Options`. Deep links answer with HTTP 404 on first load (browsers show the app normally). Files are cached for 10 minutes, so a deploy can take that long to reach everyone.
- **Google sign-in screen.** Google's consent screen names the Supabase project domain (`<ref>.supabase.co`), not Owenil. Showing your own domain needs a Supabase custom domain, which is a paid add-on. Owenil also doesn't copy the Google profile picture; it uses initials and a colour instead.
- **Node 18.** The workspace runs Node 18.17, so dependency versions are pinned to releases that support it. Node 18 is end-of-life. Upgrade to Node 22 LTS (`nvm install 22 && nvm use 22`) and then you can move to Vite 7, supabase-js latest and Playwright latest. <a id="node-18"></a>
